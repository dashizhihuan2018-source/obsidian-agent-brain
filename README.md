让知识、项目与记忆掌握在自己手中。

从零搭建或增量升级 Obsidian，将它作为 AI 智能体的通用大脑：让 GPT/ChatGPT、WorkBuddy、Trae、OpenCode、Claude Code、Codex 等围绕同一份个人知识与记忆协作。

这不是一个“装上就自动记住一切”的插件，而是一套可执行的 Skill：建库结构、空白模板、客户端接入、记忆工作协议和真实验收方法。你始终持有自己的 Markdown 文件，可以在 Obsidian 中查看、修改和备份。

项目持续更新。首次使用请从下方设置入口开始；跨会话读写需按指南完成客户端接入与权限配置。发布目的、隐私保护及第三方权利说明见 [使用与权利声明](DISCLAIMER.md)。

## 复制到 WorkBuddy，搭建个人跨软件知识库

将下面整段复制到 **WorkBuddy 桌面端的新对话**，即可让它从获取技能开始协助配置，不必先理解目录或命令：

```text
请帮我实际搭建“个人跨软件知识库”，以 Obsidian 本地 Markdown 为 AI 智能体的通用知识与记忆层，让 GPT（区分 ChatGPT 与 Codex）、WorkBuddy、Trae、OpenCode、Claude Code 等按实际能力协同；不要只介绍概念。

请从 https://github.com/dashizhihuan2018-source/obsidian-agent-brain 获取并检查「Obsidian超级大脑」完整 Skill，先阅读 SKILL.md 及本次需要的指南。若已安装，先核对版本并复用，不重复安装或覆盖已有配置。

1. 先检查操作系统、Obsidian、已有知识库，以及当前 WorkBuddy 的文件访问、技能、规则和内置记忆能力。确认我常用的软件、主要工作流程、知识库位置，以及允许读写和发送给云端模型的资料范围；不要推断我的职业、偏好或项目优先级。
2. 已有知识库就保留原目录和资料，备份要改的文件后增量接入，不移动、删除或覆盖原件、全局规则和产品内置记忆。没有知识库时，协助从 Obsidian 官网安装，在我确认的“文档/个人大脑”位置建库，并实际指导打开。
3. 首版只依赖本地 Markdown 和核心功能，建立首页、总览、收件箱、项目、长期领域、参考资料、知识卡片、每日记录、归档、智能体记忆和模板。每个项目有概览；已有外部项目记忆就链接原件，不复制详细状态。按我的实际工作方式组织导航。
4. 配置开始会话按需读取规则、MEMORY、相关待办和项目，工作前先检索，收尾分别更新长期约定、项目决定、未完成事项、每日摘要与可复用知识，并报告具体文件。不要全文扫描或保存完整聊天；事实、来源、推断和待确认内容要分开。
5. 跨软件共用同一份权威资料，先接入 WorkBuddy，GPT/ChatGPT、Codex、Trae、OpenCode、Claude Code 等由我选定后逐个核验版本、模式、实际入口、权限和读写角色；默认一个整理者，其他智能体提交唯一命名提案。不假设某文件名能自动加载，不承诺装上 Skill 就全部互通；无法自动接入时提供明确的手动读取方案，无本机权限时仅使用我批准的脱敏摘要交接。
6. 不写密码、Key、Token 等敏感信息；公司文档和他人资料先确认授权。说明云端模型可能接收哪些文件内容。不擅自上传知识库到 GitHub、网盘或远程服务，不自动购买服务、安装第三方插件、开启同步或创建定时任务。
7. 在确认的目录与权限范围内直接完成可自动执行的步骤；遇到必须由我选择、授权、安装或操作的界面时，给出具体步骤。遇到限制明确报告，不假装已读取、保存或接入。
8. 经我同意，用无隐私演示验证：首页链接、测试偏好与待办写入、全新会话指出来源文件、修改后读回最新状态、旧资料保护。无法在当前会话完成的新会话或第二客户端测试标为待我操作，演示清理也先征得同意。
9. 最后生成并从首页链接“使用指南”，教我使用“记一下”“整理这些资料”“开始一个项目”“继续上次的项目”“今天有什么要做”“今天收尾”“每周复盘”“以前研究过吗”“忘记这条信息”，说明备份恢复和新软件接入方式，并分别列出已实际验证、需要我操作、尚未验证或不支持的内容。
```

这里的“一键设置”是**复制一段话发起整套流程**，不是绕过授权或保证所有版本全自动。WorkBuddy 仍需具备相关文件访问和执行能力；无法联网、安装技能或访问本机目录时，应说明限制并给出替代步骤，而不是声称已配置成功。

显示名称为「Obsidian超级大脑」；技术标识、目录名和调用名仍为 `obsidian-agent-brain`，保持现有链接与安装兼容。

## 一份大脑，多个工作入口

Obsidian 保存权威 Markdown，客户端按任务读取；一个整理者负责精选记忆，其他智能体提交提案。更换模型或软件不必复制整套知识库，也不需要把私人库公开。

| 客户端 | 接入方向与边界 |
| --- | --- |
| GPT / ChatGPT | 先确认是桌面本地、云端还是其他 API 宿主；有本机工具时授权读取，否则只交接获准的脱敏摘要 |
| WorkBuddy | 检查当前桌面端的技能、规则和目录权限，不把内置记忆当作 vault 同步接口 |
| Trae | 在实际版本和模式中检查规则入口、触发方式与本机目录权限；入口未确认时先手动加载 |
| OpenCode | 核对 AGENTS.md / instructions 与技能发现位置；库外目录权限独立确认 |
| Claude Code | 核对 CLAUDE.md、适用版本的项目指令与文件权限；规则加载和目录访问分别验收 |
| Codex | 核对 AGENTS.md / override、技能发现和沙箱权限；云端与本机分开测试 |

这是适配方向，不是“所有客户端已自动互通”的验收声明。实际入口、来源和手动降级见 [客户端接入指南](references/integrations.md)。第一次可先选一个客户端跑通，再逐个加入；本包不安装跨客户端同步服务。

## 能做什么

- 为零基础使用者建立首页、项目、资料、知识卡片、每日记录和待办体系。
- 帮 GPT/ChatGPT、WorkBuddy、Trae、OpenCode、Claude Code、Codex 等按当前版本和权限接入同一权威记忆，不各自复制一套。
- 明确开始会话如何读取、工作中如何检索、收尾如何提炼写回。
- 对已有知识库采用增量接入，保留旧文件、配置和项目原件。
- 先研究公开项目再做适配；首页按捕获、续接、查经验和收尾组织，不复制外部项目的完整进度。
- 检查显式指定笔记的链接、越界及表格别名转义，避免为验证而读取整个私人库。
- 提供不联网、默认只预览的新库初始化器，以及新会话验收清单。

## 已有知识库：先检查，再升级

```text
请使用 $obsidian-agent-brain，先检查我的既有 Obsidian 知识库和客户端接入是否可用；如我授权升级，先研究相关公开项目，再按现有工作方式增量改进。保留目录、旧模板、原始资料和项目权威记忆，修改前备份，不把旧看板当作当前项目状态。最后分别验收文件、Obsidian 界面与目标客户端新会话。
```

模板默认只依赖 Markdown 和核心功能。新库包含项目、资料、知识卡片、每日记录，以及决策、交接、周复盘七种空白模板；已有库按需逐份合并，不整包替换配置。研究方法与来源选择见 [旧库升级指南](references/existing-vault-upgrade.md)。

## 无法自动安装时：手动导入

1. 下载本仓库 [ZIP](https://github.com/dashizhihuan2018-source/obsidian-agent-brain/archive/refs/heads/main.zip)，解压后确认能看到 `SKILL.md`、`references`、`assets` 和 `scripts`。
2. WorkBuddy 桌面端：在当前版本的技能界面选择“添加技能 → 上传技能”导入技能包并启用；具体入口以实际界面为准。如果导入不接受 ZIP 外层目录，先解压后按界面要求选包。不熟悉格式时可让 WorkBuddy 读取完整技能目录协助确认，不盲目覆盖全局配置。[官方技能说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)
3. 导入后发送上方完整提示词，并说明技能已经安装，继续执行建库和接入步骤。

如果当前客户端不能安装 Skill，把完整解压目录交给具备本机文件访问能力的智能体，明确要求先读 `SKILL.md` 及其需要的引用文件。只上传 `SKILL.md` 会缺少模板和指南。无本机访问能力时只能先讨论方案或使用获准的脱敏快照，不能假装已经配置电脑。

### Codex 安装

按照当前官方文档，用户技能可放在 `$HOME/.agents/skills/`；路径和发现范围见 [官方文档](https://developers.openai.com/codex/skills)。已有同名目录时先检查，不覆盖。

```sh
git clone https://github.com/dashizhihuan2018-source/obsidian-agent-brain.git "$HOME/.agents/skills/obsidian-agent-brain"
```

Windows 可手工将完整目录复制到自己用户目录下的 `.agents/skills/obsidian-agent-brain`。开启新会话，确认技能可见，然后调用：

```text
请使用 $obsidian-agent-brain，为我建立个人知识库并接入需要的智能体。
```

技能安装只是第一步，跨项目记忆仍需实际规则入口、目录权限和新会话测试。用户环境已有其他受支持技能位置时以实际配置为准，避免同名重复安装。

## 建好的目录

```text
个人大脑/
├── 首页.md / 使用指南.md / AGENTS.md
├── 00-总览/           知识地图、项目索引
├── 01-收件箱/         临时想法和待核资料
├── 02-项目/           有目标和结束条件的工作
├── 03-长期领域/       持续维护的职责
├── 04-参考资料/       原始来源和获准资料
├── 05-知识卡片/       可复用理解与方法
├── 06-每日记录/       按真实日期记录摘要
├── 07-归档/           经确认的不活跃内容
├── 90-智能体记忆/     规则、MEMORY、TODO、接入记录和待合并提案
└── 99-模板/           项目、资料、卡片、每日记录、决策、交接、周复盘
```

已有知识库不必改成这套名称，按职责映射即可。已有源码项目的详细记忆继续放项目原目录，知识库只保留索引与必要概览。

## 每天怎么工作

早上“今天有什么要做” → 工作前“继续这个项目” → 过程中“记一下”“整理这些资料” → 完成后“本次收尾” → 需要时“每周复盘”。

长期偏好进入精简 MEMORY；项目状态回到项目；行动进入 TODO；过程进入每日记录；可复用理解形成知识卡片。每次写回报告具体文件，不把聊天中的“已记住”当作存储证据。

## 手工运行初始化器（可选）

需要 Python 3.9+，仅使用标准库。先切换到本技能目录，把路径替换为自己确认的**尚不存在**的新目录；父目录必须已存在。

```sh
python3 scripts/bootstrap.py --vault "<新知识库绝对路径>"
python3 scripts/bootstrap.py --vault "<新知识库绝对路径>" --apply
```

Windows 可改为 `py -3`。不加 `--apply` 不创建文件；已有目标（包括空文件夹）会拒绝，没有覆盖开关。脚本先生成本地模板，再由你在 Obsidian 中“打开文件夹为仓库”。没有 Python 时可手工按 `assets/vault/` 创建，不必须安装运行时。

初始化器不改 WorkBuddy/Codex 配置、不安装软件、不联网、不生成 Git 仓库、不创建 `.obsidian`；中途失败保留已生成文件供检查，不擅自删除后重试。不建议在其他进程同时写入目标父目录时执行。

## 安全与真实能力边界

- 发布仓库只有通用说明、空白模板、代码和测试，不含作者真实知识库、私有配置或会话。
- 不存密钥、Token、身份证号；公司文档和他人信息先确认授权。
- 本地保存不等于离线模型处理；云端智能体可能把读取内容发送给服务商，须遵守用户的数据范围。
- 不自动上传、同步、开远程端口、购买服务或创建定时任务。
- WorkBuddy 内置记忆与本库分开，不覆盖或软链替换，不承诺自动双向同步。
- 默认一个整理者修改精选记忆，其他智能体提交唯一提案；本包不提供自动并发写回服务。
- 手机、云端或新产品要单独确认文件访问和入口，不能笼统宣称“所有智能体已互通”。

## 验证范围

运行脚本测试：

```sh
python3 -m unittest discover -s tests -v
```

自动测试验证新库创建、只读预览、已有文件保护等行为，不代表 Obsidian GUI、WorkBuddy 新会话、Codex 新会话、云端或多设备读写已通过。每位使用者都应按验收清单在自己的客户端实测；官方说明核对日期见来源页。

对已有知识库只读检查指定笔记（替换为确认过的路径）：

```sh
python3 scripts/check_notes.py --vault "<已有知识库绝对路径>" --note "首页.md" --note "使用指南.md"
```

检查器不遍历全库，不读取链接目标正文；短名称只尝试库根和来源笔记目录，不验证标题/块锚点内容。它不代替真实界面和新会话验收。

本 Skill 不需要后台常驻服务或第三方 Python 依赖。技能格式验证和独立场景评估也不等于所有宿主实机验收。
