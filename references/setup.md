# 从零建库与旧库接入

## 1. 安装与路径

从 [Obsidian 官网](https://obsidian.md/download) 获取适合操作系统的安装包。下载、安装或修改系统前遵循当前权限；用户手动操作时给出明确步骤。不要求 Sync、Publish、付费插件或 MCP。

推荐名称“个人大脑”，位置选择用户自己的本地文档目录。路径可以不同，不把示例用户名写死。先确认它是否处于公司共享盘或自动同步目录；本地优先不代表自动排除系统云同步。

**脚本新建路线：** 在尚不存在的目标路径运行预览，确认后加 `--apply`；然后在 Obsidian 的仓库管理界面选择“打开文件夹为仓库 / Open folder as vault”，打开生成的目录。初始化器不生成 `.obsidian`，由 Obsidian 首次打开时自行创建。

**纯界面路线：** 在 Obsidian 选择“创建新仓库 / Create new vault”，命名并选位置；随后按下方目录手动创建文件，或逐个复制 `assets/vault/` 的空白模板。此时目录已经存在，不能再运行初始化器覆盖。

需要 Python 才能使用初始化器，先检查 `python3 --version` 或 Windows 的 `py -3 --version`；没有时给出手工路线或征得同意再安装。脚本只支持创建新库，不承担迁移、升级、同步、加密或自动接入。

## 2. 目录与职责

```text
个人大脑/
├── AGENTS.md                         本库工作目录的智能体入口
├── 首页.md                           人类入口与导航
├── 使用指南.md                       日常用法和能力边界
├── 00-总览/
│   ├── 知识地图.md                   按主题组织重要笔记
│   └── 项目索引.md                   活跃项目和权威记忆入口
├── 01-收件箱/                        未处理、待核、临时想法
├── 02-项目/                          有目标和结束条件的工作
├── 03-长期领域/                      持续维护的职责
├── 04-参考资料/                      资料原件或来源索引
├── 05-知识卡片/                      可复用理解、方法和结论
├── 06-每日记录/                      YYYY-MM-DD.md
├── 07-归档/                          结束或不活跃内容
├── 90-智能体记忆/
│   ├── 记忆规则.md                   读写与隐私约定
│   ├── MEMORY.md                     精选上下文和导航
│   ├── TODO.md                       跨项目行动入口
│   ├── 接入说明.md                   实际路径与客户端验收状态
│   └── 待合并/                      其他写入者的提案
└── 99-模板/
    ├── 项目模板.md
    ├── 资料模板.md
    ├── 知识卡片模板.md
    └── 每日记录模板.md
```

每个工作目录有“说明.md”，避免空目录消失。用户已有 PARA 等结构时映射职责，不为了统一命名强行重排。目录是起点，不是必须全部填满的表格。

`02-项目/<项目名称>/项目概览.md` 从模板复制，记录目标、交付物、状态、下一步和决策。已有源码项目的记忆继续放原项目目录，vault 只保留概览与位置链接；避免两个地方同时保存完整进度。跨设备绝对路径不通用，需要在各设备接入说明里分别映射，不能假设 Obsidian 双链跨 vault 自动生效。

## 3. 已有 vault

先清点顶层目录和需要修改的入口，不读取无关私密正文。提出“现有位置 → 对应职责”的简短映射。

修改前复制备份相关配置或笔记，记录备份位置及恢复方法；备份同样敏感，不放进公开发布目录。逐个确认文件冲突，合并新增段落，不替换整份 `AGENTS.md`、`MEMORY.md` 或 `.obsidian`。不直接修改客户端自动维护的原生记忆目录。

初始化器遇到任何已有目标（含空目录和符号链接）都会拒绝。不要添加 `--force` 绕过它，也不要清空旧库后再初始化。旧库路线采用人工增量编辑，保留原件、历史版本与用户自己维护的组织方式。

## 4. 让知识库真的可用

- 首页链接到收件箱、项目索引、知识地图、待办和指南。
- 重要资料附来源、获取日期、适用项目与隐私级别；书籍/PDF 未阅读时只做索引，不虚构摘要。
- 知识卡片一篇一个主题，用自然语言链接相关资料；不是为画关系图而制造无意义双链。
- 从一项真实、获准的小任务开始，不批量导入整个硬盘、邮箱、聊天或公司网盘。
- 关闭或不安装未审查的第三方插件，原生搜索、链接和模板足以完成首版。

## 5. 本地备份与恢复

先提出方案，不默认开启云同步。最小方案是用户选定的独立位置上的版本化文件夹副本；备份 vault 正文及必要配置，遵守原资料权限。同步会传播误删，不等于备份；有敏感内容时选择用户认可的加密备份方式，普通目录复制本身不加密。

恢复演练在临时副本中完成：复制一份备份到不同路径，检查笔记、附件和链接，再用 Obsidian 打开该副本；不要用演练覆盖当前 vault。跨设备同步或 Git 备份需要另外明确访问人员、冲突策略和隐私范围。
