# 验收与交付

脚本测试只能证明建库器对应行为；客户端真实使用必须独立验证。使用明确标记为演示的无隐私数据，不把测试偏好留成用户真实画像。

## 验收表

| 层级 | 操作 | 成功证据 |
| --- | --- | --- |
| 文件 | 检查目录、模板、根入口与实际绝对路径 | 文件存在、内容可读、占位路径已替换 |
| Obsidian | 打开目录为仓库，点击首页/指南/待办等链接 | 实际界面中笔记打开正确；仅文本检查不算 GUI 验收 |
| 首次写入 | 用户授权加入“演示偏好：测试摘要限三行”和测试待办 | 实际目标文件内容，而非聊天中声称已保存 |
| 跨会话 | 在目标客户端新建会话，仅要求读取演示偏好和待办，不提供答案 | 正确读回并指出来源文件；记录是否需要手动触发 |
| 更新 | 将测试待办标记完成，再在新会话查询 | 新状态与文件一致，无缓存旧值 |
| 第二客户端 | 在另一个客户端读同一条演示记忆 | 真实读取的路径、条目与状态一致 |
| 角色/冲突 | 第二客户端按约定创建唯一提案，由整理者合并 | 两端信息保留，精选记忆未被旧副本覆盖 |
| 失败分支 | 用不存在的测试路径发起只读请求 | 客户端报告访问失败，不声称读取成功；不修改真实权限来制造故障 |
| 原件保护 | 对比修改清单与备份 | 旧资料及无关配置未被覆盖 |
| 清理 | 征得同意后删除演示条目和已处理测试提案 | 回读确认；不把演示内容存入长期真实记忆 |

无法打开另一个客户端或无法发起全新会话时，将该行记“待用户执行”，给可复制测试语句，不用同一会话模拟当作实测。用户未要求接入第二客户端时记“不在本次范围”。

示例新会话测试语句：

```text
请按已经配置的知识库入口，告诉我演示偏好的内容、测试待办当前状态，以及你读取的来源文件；无法读取请直接说明，不要猜测。
```

## 最终交付必填项

- 知识库实际位置、入口与目录职责。
- 修改及新增文件、配置备份位置、恢复方法。
- 每个客户端的版本/模式、入口范围、写回角色、最后实测日期。
- 已实际验证、待用户操作、未验证/不支持分别列出。
- 使用指南中的常用指令和一天的工作流程。
- 隐私选择、本地/云端边界、备份与并发限制。

## 维护者发布检查

分享的是 Skill，不是用户知识库。使用独立干净仓库，仅加入通用说明、空白模板、脚本和测试；检查隐藏文件、软链接、附件、Git 历史和提交者邮箱。不得包含用户实际路径、真实记忆、凭证、会话日志、配置备份或内网地址。

发布前运行：

```sh
python3 -m unittest discover -s tests -v
```

有 skill-creator 验证器时另做 frontmatter 验证；结构通过不代表行为通过。按真实场景独立检验旧库保护、未知客户端和并发降级。公开发布要有用户当次授权，完成后匿名读取远端内容并核对提交及包内容，不以 push 返回成功替代最终可访问验证。
